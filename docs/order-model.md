# 委托模型：触发型委托与有效期

本轮在不改动上一轮既有状态流转、拒单原因体系与账户恒等式口径的前提下，
把委托模型加厚为：触发型委托（止损 / 止损限价 / 跟踪止损）、
有效期（DAY / IOC / FOK / GTC）、交易日边界（收盘、跨日盯市）。

## 1. 委托类型（`event.OrderType`）

| 类型 | 字段 | 触发前 | 触发后 |
| --- | --- | --- | --- |
| `Market` (1) | — | 无触发阶段 | 立即吃对手簿 |
| `Limit` (2) | `Price` | 无触发阶段 | 立即穿越 + 挂簿 |
| `Stop` (3) | `StopPrice` | 等待触发 | 转为市价单 |
| `StopLimit` (4) | `StopPrice` + `Price` | 等待触发 | 转为限价单 |
| `TrailingStop` (5) | `TrailPct` 或 `TrailAmount`（二选一） | 等待触发 | 转为市价单 |

### 触发判定价

同一事件流中买卖两侧使用不同判定价，贴近实盘语义：

- 买入止损（`Side=BUY`）：用**卖价**（`AskPrice`）判定，向上触及/突破 `StopPrice` 触发。
- 卖出止损（`Side=SELL`）：用**买价**（`BidPrice`）判定，向下触及/跌破 `StopPrice` 触发。
- 成交流事件（`KindTrade`）没有买卖两侧，用 `TradePrice` 判定。

### 触发前的账户语义

- 触发型委托在 `WAITING_TRIGGER` 状态下**不冻结资金、不冻结持仓、不参与撮合**，
  任何行情都不会使其产生成交。
- `Engine.Snapshot()` 的 `WaitingTrigger` 列表可以看到全部待触发委托；
  其不存在于 `OpenOrders`，账户 `FrozenCash` / 持仓 `Frozen` 中也没有它的痕迹。

### 触发只发生一次

- 每个行情事件上，每张待触发委托至多评估一次；触发瞬间记录
  `TriggerPrice`、`TriggeredSeq`，之后**锚点与触发价全部冻结**，
  任何后续行情（继续大涨/大跌、重复事件）都不会二次触发、二次成交。
- 同一批事件无论乱序投递、并发投递、重复投递多少遍，引擎统一按
  `(Seq, EventID)` 排序应用、按 `EventID` 幂等去重，
  被触发的委托、触发后的成交与账户结果完全一致。
- 不同标的的触发条件、订单簿互相独立；日终失效按整日收口（见下）。

### 跟踪止损（TrailingStop）

基准 `AnchorPrice` 只能朝有利方向移动，触发后不再变化：

- 卖出跟踪：锚点取已观测到的最高买价，**只升不降**；
  当 `买价 <= Anchor - 回撤` 时触发。
- 买入跟踪：锚点取已观测到的最低卖价，**只降不升**；
  当 `卖价 >= Anchor + 回撤` 时触发。
- 回撤二选一：
  - `TrailAmount`：绝对价差；
  - `TrailPct`：相对当前锚点的比例，`gap = Anchor * TrailPct`。
- 锚点初值：提交时若已有盯市价，以该价格初始化；否则等第一笔行情。

### 触发瞬间资金/持仓不足

触发后需要像普通委托一样先冻结再撮合。若此刻资金或持仓不足：

- 订单直接进入 `REJECTED`，拒单原因与普通下单不足严格区分：
  - 买入：`TRIGGER_INSUFFICIENT_CASH`
  - 卖出：`TRIGGER_INSUFFICIENT_POSITION`
- **不产生任何成交、不留下任何冻结**（触发前本就无冻结，触发失败也不会新冻）。
- 可用资金、可用持仓、权益拆解在拒单后立刻回到可解释状态（快照对账通过）。

### 触发前撤单

- `WAITING_TRIGGER` 可以撤单；部分撤单（`Qty>0` 小于剩余量）后继续等待触发。
- 已经触发并进入 `NEW/PARTIALLY_FILLED` 的委托走普通撤单路径。
- 已结束（`FILLED/CANCELED/REJECTED/EXPIRED`）的委托再撤、再操作，
  沿用老规矩 `TERMINAL_ORDER` / `ORDER_EXPIRED` 拒绝。

## 2. 有效期（`event.TIF`）

| TIF | 语义 |
| --- | --- |
| `DAY` (1) | 当日有效；当日收盘未成交完、未触发的，日终统一失效 |
| `IOC` (2) | Immediate-Or-Cancel：立即撮合，能成多少成多少，剩余立刻撤销并释放冻结 |
| `FOK` (3) | Fill-Or-Kill：本次撮合必须全部成交，否则整单一点不成交 |
| `GTC` (4) | 长期有效，直到成交/撤单 |
| `Unset` (0) | 未指定；按 `GTC` 解释，兼容上一轮调用方，旧行为不变 |

### FOK 原子性

- 撮合前先做足额预检（对手簿可成交量 + 当前盘口对手价穿越量）。
- 预检失败：**零成交**，订单 `CANCELED`，买入冻结资金 / 卖出冻结持仓
  全部原路释放，任何时点都不存在"成交了一部分再撤剩余"的中间状态。
- 预检成功：整单全部成交，不允许残留。
- FOK 同样适用于触发型委托：触发后的可成交量不足时整单取消，无任何成交。

### IOC

- 立即按对手簿/盘口成交；零成交也允许（订单 `CANCELED`）。
- 剩余量立刻撤销，冻结按分段（见下）释放干净，`FrozenCash` 归零。

### DAY

- 未成交完的当日挂单、未触发的当日条件单，在当日收盘事件中统一失效；
  收盘按整日收口，一个收盘事件即失效所有标的的当日单（详见
  `trading-day.md`）。
- 收盘后再来行情、成交、撤单请求：订单已是 `EXPIRED` 终态，
  撤单返回 `ORDER_EXPIRED`，行情不会让它再成交。

### 冻结分段（实现细节）

买入冻结在订单上以 `(qty, refPrice)` 分段记录。部分成交时按成交数量
逐段核销冻结并以该段参考价与实际成交价多退少补，撤单/失效也按分段释放，
因此同一张单在不同价位分批成交不会污染账户恒等式。
