# 回测撮合引擎：委托模型扩展（触发型委托 / 有效期 / 交易日边界）

本轮在不改动上一轮事件驱动撮合、账户核算、幂等/并发语义的前提下，把委托模型做厚：

- 新增三类触发型委托：止损（`STOP_MARKET`）、止损限价（`STOP_LIMIT`）、跟踪止损（`TRAILING_STOP`）；
- 新增有效期维度：`DAY`（当日）、`IOC`（立即成交否则取消）、`FOK`（全部成交否则取消）、`GTC`（长期）；
- 新增交易日收盘事件 `SESSION_CLOSE`，支持日终失效、收盘价盯市、日终快照、跨日续跑。

## 1. 触发型委托

### 类型与触发规则

| 类型 | 触发前 | 触发条件 | 触发后 |
| --- | --- | --- | --- |
| `STOP_MARKET` | `WAITING_TRIGGER`，不撮合、不成交 | 买：价格 ≥ 止损价；卖：价格 ≤ 止损价 | 按市价单立即成交 |
| `STOP_LIMIT` | 同上 | 同上（`StopPrice`） | 转为普通限价单（`LimitPrice`），走同一条撮合路径 |
| `TRAILING_STOP` | 同上 | 从最有利基准回撤 `TrailDistance`（绝对价差）或 `TrailPct`（比例，二选一） | 按市价单立即成交 |

- 触发判定价格取该标的最新事件价：成交流成交价优先；只有报价时取买一/卖一中点。
- 跟踪止损基准 `TrailAnchor` 只朝有利方向移动：卖出方向跟历史最高价（回撤卖出），买入方向跟历史最低价；触发后基准冻结，不再变化。
- 卖出跟踪止损示例：基准从 100 上移到 112，`TrailPct=0.05` 时，价格 ≤ 112×0.95 = 106.4 才触发；中途反弹不会抬高/降低基准。
- 触发前委托状态为 `WAITING_TRIGGER`，在 `Engine.Snapshot()` 的委托视图中可见；**触发前不占用资金、不锁定持仓**，账户快照里只看到待触发状态，看不到对应冻结。
- 触发后与普通委托完全同路：同样的冻结、成交、撤单、有效期与账户核算逻辑。

### 触发只发生一次（幂等/乱序/并发）

- 触发即把委托移出待触发集合并置 `Triggered=true`，之后同一批行情/成交流无论重复投递多少遍、顺序如何，都不会二次触发。
- 每批事件按 `(Seq, EventID)` 确定性排序，所有入口在单把互斥锁内串行；触发产生的成交与账户结果只由事件集合决定，与到达顺序、并发方式无关。
- 触发评估按标的分桶（`waiting[symbol]`），不同标的的触发互不影响。

### 触发瞬间资金/持仓不足

- 冻结发生在触发的那一刻：买入调 `ReserveBuy`、卖出调 `ReserveSell`。
- 不足则整单直接拒掉，拒单原因与普通下单区分：
  - `TRIGGER_NO_CASH`：触发时买入资金不足；
  - `TRIGGER_NO_POSITION`：触发时卖出持仓不足。
- 拒绝路径不产生任何成交、不留下冻结资金或锁定持仓；之后可用资金、可用持仓与权益拆解仍对得上（账户恒等式每次操作后都校验）。

### 撤单

- `WAITING_TRIGGER` 委托可以整单撤销（进入 `CANCELED`），也支持部分撤单（只缩减数量，继续待触发）。
- 已触发但未成交完的委托与普通委托一样可撤。
- 已终态（成交/撤销/拒单/过期）的委托再撤单或做其它操作，沿用老规矩：`TERMINAL_ORDER` / `EXPIRED_ORDER` 拒掉。

## 2. 有效期（TimeInForce）

| TIF | 语义 |
| --- | --- |
| `DAY` | 当日有效（默认；事件 TIF 为零值时按 DAY 处理，兼容旧事件），日终未结束自动过期 |
| `IOC` | 立即成交否则取消：能成多少成多少，剩余立即撤销，对应冻结立即释放干净 |
| `FOK` | 全部成交否则取消：**原子**——本次撮合能全成才成交，否则整单一点不成，不存在“先成一部分再撤剩余”的中间状态 |
| `GTC` | 长期有效：日终不过期，跨交易日继续挂单、继续盯市/触发 |

- FOK 的原子性在撮合层保证：撮合前先试探当前事件/盘口顶档可用量，不足整单数量则直接不成交，委托转 `CANCELED` 且原因标记 `FOK_NOT_FILLED`，`FilledQty` 恒为 0。
- 市价单（含触发后的止损市价单）吃不完的剩余立即撤销，原因沿用既有的 `NO_LIQUIDITY` 口径。
- 有效期对触发型委托同样适用：`DAY` 条件单当天没触发，日终与普通当日单一起失效；`GTC` 条件单跨日继续等待触发。

## 3. 交易日收盘与跨日

### 收盘事件

- 事件 `Kind = SESSION_CLOSE`，字段 `TradeDate`（交易日标签，如 `2026-10-06`）、`Symbol`（可空）、`ClosePrice`（>0 时作为该标的收盘价盯市）。
- 可以按标的投递多条带收盘价的收盘事件，也可以投递一条无标的的全局收盘事件统一触发日终。
- 每个交易日只有第一次收盘真正结算：
  - 未成交完的 `DAY/IOC/FOK` 活动单、未触发的 `DAY` 条件单统一进入 `EXPIRED` 终态，并释放剩余冻结；带部分成交的委托保留已成交部分；
  - `GTC` 单（含触发后转成的 GTC 活动单）保留；
  - 已终态/已失效的委托不二次失效、不重复退钱退货；
  - 收盘价写入盯市，随后产出 `DaySnapshot`（账户快照 + 当时的委托视图）。
- 同一交易日的收盘事件重复投递：幂等返回（结果置 `Duplicate`），不重复结算。
- 已收盘后再来当日行情/委托/撤单：以 `SESSION_CLOSED` 拒绝；对已过期委托再操作：`EXPIRED_ORDER`。

### 自动日切

- 事件带 `TradeDate`，当新日期的首个事件到达而前一交易日尚未显式收盘时，引擎先自动收掉前一交易日（同样产生日终快照），再处理新事件——漏发收盘事件也不会破坏隔夜语义。

### 跨日对账

- 隔夜仓位继续按后续行情/收盘价盯市，未实现盈亏逐日累计；权益恒等式与逐笔快照完全同口径：

```
权益 = 现金 + 冻结现金 + Σ(持仓数量(含冻结) × 最新价)
     = 初始资金 + 已实现盈亏 + 未实现盈亏 − 累计费用 + 公司行为调整
```

- 日终快照若拆不平，收盘事件直接以对账错误拒绝（`portfolio.ReconcileError` 明细），绝不静默吸收。
- 日终批量失效与行情/成交事件并发到达时，因排序 + 单锁串行，最终结果不随到达顺序变化（有专项测试）。

## 4. 与原有行为的兼容边界

- 旧的委托状态流转不变：`PENDING_NEW / NEW / PARTIALLY_FILLED / FILLED / CANCELED / REJECTED` 全部保留；新增状态仅为 `WAITING_TRIGGER / TRIGGERED / EXPIRED`，其中 `EXPIRED` 也视为终态。
- 旧的拒单原因枚举一个不动，新增原因均为新字符串：
  `INVALID_TIF`、`INVALID_STOP_PRICE`、`INVALID_TRAIL`、`TRIGGER_NO_CASH`、`TRIGGER_NO_POSITION`、`SESSION_CLOSED`、`EXPIRED_ORDER`、`FOK_NOT_FILLED`。
- 旧事件（不带 TIF）按 `DAY` 解释；旧的市价/限价单、撤单、公司行为（拆股/分红）语义不变。
- 事件模型只做字段/枚举新增，未删除或重编号任何既有字段。

## 5. 主要 API

- `engine.New(portfolio.Portfolio)`：创建引擎。
- `Process([]event.Event) []Result`：批量投递（内部排序、幂等、串行）。
- `ProcessOne(event.Event) Result`：单条投递；重复 EventID 返回首次结果并置 `Duplicate=true`。
- `Snapshot() (portfolio.Snapshot, []OrderView, error)`：当前账户快照与全部委托视图（含 `WAITING_TRIGGER`）。
- `GetDaySnapshot(date) *DaySnapshot` / `ClosedDates()`：日终快照与已收盘交易日。
- 委托提交事件新增字段：`TIF`、`StopPrice`、`TrailDistance`、`TrailPct`；事件新增 `TradeDate`、`ClosePrice`。

## 6. 本地验证

一条命令跑完所有包的全部用例（业务分组汇总只在 `-v` 输出中展示）：

```bash
go test -v -count=1 ./...
```

并发数据竞争检查（需要 cgo）：

```bash
CGO_ENABLED=1 go test -race -count=1 ./...
```

输出按业务分组汇总每组用例数与通过/失败数，当前覆盖：

- engine：基础撮合（9）、触发型委托（10）、有效期（8）、交易日边界（7）、回放压测（3），共 37 个；
- portfolio：账户核算（7）。

回放压测用例构造 4.8 万条事件、跨 5 个交易日的混合序列（限价/市价/IOC/FOK/止损单 + 行情 + 日终），
校验对账恒等式、耗时/堆内存占用（40MB 量级）以及“并发重复整批投递 vs 串行投递”结果完全一致。
