# 交易日边界：收盘、日终快照与跨日盯市

## 收盘事件（`KindDayClose`）：一次收盘，收口一整天

字段：

- `TradingDay`：交易日序号（建议从 1 起单调递增）。填 0 时由引擎按收到顺序推断。
- `Symbol`：**可选**。只用于收盘价盯市，不影响收口范围。
- `ClosePrice`：收盘价。`> 0` 且 `Symbol` 非空时更新该标的盯市价。

一个收盘事件把**整个交易日**收干净，与事件带没带标的、带的是哪个标的无关：

1. 校验交易日序号：`TradingDay` 不允许倒退，倒退返回 `STALE_TRADING_DAY`。
2. `Symbol` 非空且 `ClosePrice > 0` 时，把该标的的最新价 / 买价 / 卖价 /
   盯市价统一更新到收盘价。不带标的的收盘只做收口，不会在行情或盯市里
   凭空多出一条空标的的记录。
3. **所有标的**的 `DAY` 委托批量失效（按 `(提交Seq, OrderID)` 确定序）：
   - `WAITING_TRIGGER` 的当日条件单（未触发）；
   - `NEW / PARTIALLY_FILLED` 的当日挂单（未成交完）。
   - 失效订单进入 `EXPIRED`，冻结资金 / 冻结持仓一次性原路退回，
     不漏也不多退，不产生成交。失效单号在 `Result.ExpiredOrderIDs` 中返回。
4. GTC 单（含 GTC 条件单）不受影响，隔夜继续挂着 / 继续等待触发。
5. 收盘完成后固化该交易日的日终快照（见下节）。

多标的多天回放的典型用法：每天收盘时只投**一个**收盘事件
（带不带标的均可），不需要逐标的投递。

## 日终快照（`DayEndSnapshot`）

收盘完成后可以取到这一天固化的日终快照：

```go
snap, ok, err := eng.DayEndSnapshot(day)
```

- `ok=false`：该交易日尚未收盘。
- `err`：收盘对账时的 `portfolio.ReconcileError`。权益拆解对不上会明确
  报出，绝不静默吞掉。
- `snap`：`AccountSnapshot`，含权益以及现金、冻结现金、持仓、
  已实现/未实现盈亏、费用、公司行为等完整拆解（`snap.Portfolio`），
  以及当日全部委托的终态视图。权益口径与即时 `Snapshot()` 完全一致：

```
权益 = 现金 + 冻结现金 + Σ(可用持仓 + 冻结持仓) × 最新价
     = 初始资金 + 已实现盈亏 + 未实现盈亏 − 累计费用 + 公司行为调整
```

快照在收盘那一刻固化：之后继续投事件不会改变历史某一天的日终快照，
每个交易日的快照各自独立可取。

## 幂等与重复收盘

- 收盘事件本身走全局 `EventID` 幂等：相同 `EventID` 重复投递返回首个结果。
- 同一 `TradingDay` 即使换了 `EventID` 重复收盘，也**不会**二次失效、
  二次释放冻结、二次改动盯市价，返回的 `ExpiredOrderIDs` 为空，
  日终快照内容不变。
- 已 `EXPIRED` 的订单不会被二次失效；对其撤单返回 `ORDER_EXPIRED`，
  第二天再投递任何行情都不会让它成交，未触发的当日条件单也不会再触发。

## 跨日盯市与权益拆解

- 持仓跨日保留，第二天新的行情/收盘价继续更新盯市价，浮动盈亏连续累积，
  已实现盈亏不重算、不回滚；切日不会破坏权益拆解。
- 账户恒等式在每个事件后校验，跨日也不例外；拆不平时
  `Snapshot()` / `DayEndSnapshot()` 返回 `portfolio.ReconcileError`。

## 同一账户自撮（内部记账）

回测里同账户自己的买卖单可能互相成交。此时两腿价款净额为 0、两腿费用照扣、
总股数不变（可用 +qty、冻结 -qty），卖腿按成交前均价结转已实现盈亏，
买腿把成交价并入成本基，由 `portfolio.FillSelfCross` 在一把锁内原子记账，
避免先改均价再结转导致的权益拆不平。

## 并发与顺序

`Submit` 只入缓冲、不改变状态；`Drain()`/`Process()` 取出缓冲后按
`(Seq, EventID)` 稳定排序再顺序应用。因此日终批量失效与行情、成交流、
委托事件即使并发到达、乱序到达、重复到达，最终账户与订单状态只取决于
事件内容，不取决于到达顺序。`go test -race` 通过。

## 兼容边界

- 上一轮"按标的逐个收盘"的语义已调整为"整日收口"：旧用法（每天给每个
  标的各投一个收盘事件）仍然安全——第一个收盘事件完成整日收口，其余
  同交易日的收盘事件按重复收盘幂等处理，不会二次失效或重复退钱退货。
- 其余事件类型、委托模型、拒单原因、账户口径全部保持不变，
  详见 `compatibility.md`。
